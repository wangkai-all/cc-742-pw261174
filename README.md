# 文本编码分析台

一个**离线、零依赖、不调用任何大模型**的文本编码分析台，用于核对两名编码者对同一批虚构意见文本的人工字符区间标注。

所有文本均为虚构示例（见 `data-source/corpus.js` 的说明与 `src/data/corpus.json` 的 `meta.disclaimer`）。所有主题判断都直接来自样例中的人工标签：程序只做区间对齐、坐标迁移、分歧归因、构成调整和漂移检验，不预测、不补全、不推断任何主题。

## 运行

```bash
npm start          # http://127.0.0.1:4173/
npm test           # 50 项单元测试 + 自检引用实现
npm run build:fonts  # 按当前源码与语料重新子集化字体（需要 .tools 里的构建依赖）
```

无需 `npm install`：服务端只用 Node 内置模块，前端只用浏览器 ES 模块。字体是本地子集化的 Noto Sans SC（`public/vendor/fonts/`），CSP 禁止一切外部资源与模型调用。

## 它要回答的问题

> 一段意见可能同时涉及几个主题，两名编码者对句段的切分也不一样。怎样才能公平地比较他们的主题判断？

直接把整篇文档的标签集合拿来比是错的：两人都用了 `noise` 和 `parking`，并不说明他们把同样的意思放到了同样的位置。本台的做法是：

1. **先对齐，再比较**。把两人标注区间的重叠关系看成一张图，取连通分量作为 *对齐区域*（`src/core/align.js: alignedRegions`）。区域是两个编码者真正在争论的单元。
2. **把分歧分开归因**（`src/core/attribute.js`）：区域的标签集合相同但切分不同 → **边界分歧**；标签集合不同 → **主题分歧**；只有一方标注 → **漏标**。逐字符对照只作为验证用的参照实现，两个数字在页面上并排显示，并且自检会核对它们互相一致。
3. **修订后不直接搬坐标**（`src/core/migrate.js`）：把旧区间映射到新文本，只在位置被文本唯一确定时才自动落位；有多个同等可信位置或原文被删时进入**争议区**，由裁决层处理，绝不偷偷挑一个副本。
4. **漂移要看构成**（`src/core/drift.js`）：每个主题的占比序列都算两遍——原始观测，以及按全期批次构成重新加权后的序列。只有重新加权后仍然显著的趋势才算个人标准变化；原始序列看着变了但重加权后不见了，判为「批次构成变化，非个人漂移」。
5. **裁决是独立层**（`src/core/overlay.js`）：原始标注只读。裁决以追加记录的形式存在，带文本版本号；版本不符的记录显示为「过期」而不是套到新坐标上。撤销也是一条记录。

## 页面

| 视图 | 内容 |
|---|---|
| 总览 | 语料规模、整体一致性、逐篇归因表、构造设计（时间窗构成的移动） |
| 文档对齐 | 双栏字符级渲染（含重叠区间、多主题）；拖选任意字符区间即可新建一段标注；逐段对照表；分歧贡献条 |
| 修订迁移 | 修订操作色带、逐字符状态、标注迁移候选、争议区；重复出现的文字会列出全部候选 |
| 争议裁决 | 争议清单、候选选择、替换/拆分/合并/驳回、追加式记录；**原编码 / 裁决** 一键切换对比 |
| 漂移 | 原始 vs 构成调整两条小倍图；Theil–Sen 斜率与置换检验 p 值；构成效应；漂移样例下钻 |
| 示例与自检 | 四个构造边界情形（重复文字、交叠标签、中途插入、整句删除）实时核对；在浏览器里跑 `verifyCorpus()`：区间扫描、逐字符参照、主题贡献、覆盖、区块、迁移暴力枚举 |

拖选说明：在任一栏的文本上按下并拖动，松开即创建一个待定区间；默认继承该栏当前主题选择，可在弹层里多选主题、调整起止点。落到已有标注上的新区间与旧区间**并存**（允许交叠），不会被合并或覆盖。

## 算法要点与可核对性

- **区间语义**：全部是半开区间 `[start, end)`，字符坐标，不做文本规范化。
- **反复出现的文字**：迁移不猜。若整个区间在新区间里有不止一处可落，判为 `ambiguous` 并列出全部候选；页面上可以逐个预览。
- **任意对齐枚举**：`verify.js` 里保留了一个纯暴力的参照实现（穷举所有最优 LCS 对齐），在小片段上与逐字符参照互证（`migration:slices`）。
- **两种定位器**：`locateSpanExact` 是「所有最优对齐」语义的精确实现，用作参照；`locateSpan` 是面向审阅者的块锚定策略（要求一段连续文字存活，避免把一句被删除的汉语里散落的 `的`、`。` 当成可迁移的痕迹）。两者判定不同时，迁移表会显式标出 `policyDiffers`。
- **确定性**：置换检验用 mulberry32 + 固定种子 20261124，同一输入必然得到同一 p 值。
- **构造样例即测试**：`src/core/examples.js` 里的四个边界情形（重复文字、交叠多标签、中途插入、整句删除）每页实时重算并与逐字符参照比对；`tests/examples.test.js` 对同一批结果做断言，页面与命令行不会各说各话。

```

```

## 已知边界

- 语料只有 25 篇、5 个时间窗，置换检验的效力有限；页面会同时给出 p 值与逐窗序列，不把单个 p 值当结论。
- w1 没有 S 类文档，构成调整在该窗只覆盖部分参照构成，`coverage` 会低于 1，页面显式标注，不做插补。
- 颜色对照度不足的槽位一律配直接标签或表格视图（不单靠颜色区分）。
